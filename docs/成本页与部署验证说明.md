### 3. 若仍无法 SSH（原因与推荐方式）

- **现象**：连接在「密钥交换」阶段被关闭（`kex_exchange_identification: Connection closed by remote host`）。
- **根因（已确认）**：服务端日志为 `banner line contains invalid characters` / `invalid format`。即 **sshd 认为客户端发来的首行（版本字符串）含非法字符**。当前实例上从本机 SSH 到 127.0.0.1 可正常完成 kex，说明问题出在**你本机 SSH 客户端**（如 macOS 自带的 OpenSSH + LibreSSL）发出的首行被 AL2023 的 sshd 拒绝。
- **推荐方式（无需 SSH）**：使用 **AWS Systems Manager Session Manager** 进实例（已为实例角色附加 `AmazonSSMManagedInstanceCore`，可直接用）：
  ```bash
  aws ssm start-session --target i-0af2e2ce16237e972 --region ap-northeast-1
  ```
  进入后即为 ec2-user 的 shell，可执行 `sudo`、查看/修改 sshd 配置、查看日志等。
- **若必须用 SSH**：
  1. **换客户端**：在另一台机器（如 Linux 或未受影响的 Mac）上 SSH；或在本机安装 Homebrew OpenSSH（`brew install openssh`）并用其 `ssh` 替代系统自带的。
  2. **控制台**：`aws ec2 get-console-output --instance-id i-0af2e2ce16237e972 --latest` 查看 user-data/sshd 是否执行。
  3. **EC2 Instance Connect**：在 AWS 控制台该实例页「连接」→「EC2 Instance Connect」用浏览器内 SSH 试一次。
